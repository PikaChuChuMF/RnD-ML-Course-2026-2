# Rossmann Store Sales | ДЗ1 по ML R&D

Исторические признаки снизили RMSPE на последнем 42-дневном окне с **20,33% до 15,61%**. Это **23,2% относительного улучшения** при согласованном пороге 5%.

## 1. Постановка задачи

Прогнозируем дневную выручку каждого магазина Rossmann на шесть недель вперед. Такой прогноз помогает планировать график сотрудников. Все 42 прогноза для магазина делаем из одной точки времени. Горизонт взят из постановки конкурса. [Rossmann Store Sales на Kaggle](https://www.kaggle.com/c/rossmann-store-sales)

В работе проверяем локальный 42-дневный прогноз для всей наблюдаемой сети из 1115 магазинов. Официальный `test.csv` охватывает 48 дней, с 1 августа по 17 сентября 2015 года, и 856 магазинов. Его используем только для описания и дополнительной проверки состава магазинов на локальном окне.

> **Гипотеза.** История продаж существенно повышает точность прогноза дневной выручки. Модель, использующая информацию из истории, покажет меньшую ошибку, чем та же модель без признаков из истории.

Существенным считаем снижение RMSPE хотя бы на 5% относительно модели без исторических признаков. Порог выбрали до эксперимента.

## 2. Формализация

| Что | Определение |
|---|---|
| Тип задачи | Прогнозирование числовой величины по нескольким временным рядам |
| Единица наблюдения | Пара `Store` и `Date` |
| Цель `y` | Дневная выручка `Sales` |
| Признаки `X` | Идентификатор магазина, день недели, месяц, запланированное промо. Для второй модели добавляем признаки из продаж до даты прогноза |
| Одно предсказание | Неотрицательная оценка выручки магазина на указанную дату. Для заранее известного закрытия прогноз равен нулю |

Предполагаем, что запланированные промо (`Promo`) и расписание открытий (`Open`) известны на все 42 дня в момент прогноза. `Open` используется только для правила о закрытии. В официальном тесте у магазина 622 есть 11 строк без `Open`. Для конкурсного прогноза по этим строкам понадобится отдельное правило.

## 3. Данные и EDA

В `train.csv` **1 017 209** строк по **1115** магазинам, с 1 января 2013 по 31 июля 2015. Есть числовые поля выручки и числа покупателей, идентификатор магазина, дата, признаки открытия, промо и праздников. Ключ `Store, Date` уникален. Пропусков в исходных полях нет. [Описание данных](https://www.kaggle.com/c/rossmann-store-sales/data?select=sample_submission.csv)

- У **180 магазинов** отсутствуют все **184 дня** с 1 июля по 31 декабря 2014 года. Это пропущенные наблюдения, которые могут оставить признак продаж год назад без значения. На основном окне у **5030** строк с положительной выручкой нет наблюдения за 364 дня до прогнозируемой даты. Для них применяем заполнение, описанное в разделе 4. [Обсуждение пропуска данных на Kaggle](https://www.kaggle.com/c/rossmann-store-sales/forums/t/16856/missing-data-180-stores-several-months/95225)
- **172 871** строка с нулевой выручкой. Из них **172 817** относятся к закрытым магазинам, еще **54** помечены как открытые. Последние требуют осторожности при интерпретации.
- Медиана положительной выручки равна **6369**. Первый и 99-й перцентили равны **2188** и **17 789**. Крайние значения могут быть реальными всплесками, поэтому их сохраняем и отдельно смотрим чувствительность к ним.
- Утечка может возникнуть из-за фактического `Customers` за день прогноза, выручки из окна прогноза в расчете признаков или случайного перемешивания дат. Для модели используем только перечисленные в разделе 2 признаки.

Графики выручки по дням недели и промо, а также распределение положительных продаж есть в [ноутбуке с анализом](notebooks/analysis.ipynb).

## 4. Baseline

Сравниваем две **линейные регрессии**. Первая получает магазин, день недели, месяц и `Promo`. Вторая получает те же признаки плюс шесть характеристик истории.

| Исторический признак | Как считаем до даты прогноза |
|---|---|
| Медиана магазина | Медиана положительных продаж магазина |
| Медиана по магазину и дню недели | Медиана положительных продаж для того же дня недели |
| Недавняя выручка | Средняя положительная выручка за последние 28 дней |
| Тренд | Разница между средней положительной выручкой за последние 28 дней и за предыдущие 28 дней |
| Продажи год назад | Выручка за дату на 364 дня раньше, чтобы сохранить день недели |
| Типичная выручка в промо | Медиана положительной выручки в прошлые промодни. Признак включается для запланированных промодней |

Если в истории не хватает данных, для типичной выручки используем медиану магазина или общую историческую медиану. Пропуск продаж год назад заменяем медианой по магазину и дню недели. Тренд при отсутствии одной из частей истории равен нулю.

Магазин, день недели и месяц кодируем через one-hot. Числовые признаки стандартизируем. Обе модели обучаем на положительной выручке с целью `log1p(Sales)`. Прогноз возвращаем в исходную шкалу через `expm1` и ограничиваем снизу нулем. Настройки линейной регрессии одинаковые, с intercept и без подбора параметров. Это дает простой контрольный эксперимент, в котором меняется набор признаков.

## 5. Протокол оценки

Основное окно с **20 июня по 31 июля 2015**, всего 42 календарных дня. В нем **46 830** строк, из которых **40 282** участвуют в расчете метрик. Для проверки повторяемости используем еще два последовательных окна по 42 дня.

1. Обучающие примеры строим на более ранних 42-дневных окнах. Для каждого окна используем продажи строго до его начала. Для основного прогона обучаемся на **747 397** строках с положительной выручкой, с 2 марта 2013 по 19 июня 2015. Более ранняя история нужна для первых признаков.
2. Кодировщик и масштабирование обучаем отдельно на обучающей части каждого прогона. Внутри каждого окна обе версии прогнозируют одни и те же даты для одних и тех же магазинов.
3. **RMSPE** считаем как корень из среднего квадрата относительной ошибки `(прогноз - факт) / факт`. Как в конкурсе, используем строки с положительной фактической выручкой. Дополнительно считаем **MAE** на этих же строках, чтобы видеть ошибку в единицах выручки. [Правила расчета RMSPE](https://www.kaggle.com/c/rossmann-store-sales)
4. Сравниваем варианты по локальному RMSPE. Для основной гипотезы используем заранее выбранные две версии. Дополнительные варианты оцениваем отдельно по исследовательским вопросам.

## 6. Результаты

| Вариант | RMSPE | MAE |
|---|---:|---:|
| Линейная регрессия без исторических признаков | 20,33% | 931,78 |
| Линейная регрессия с историческими признаками | 15,61% | 754,71 |

Снижение RMSPE на последнем окне составило **4,72 процентного пункта**, или **23,2% относительно модели без истории**. 95% бутстрап-интервал для относительного улучшения составил **от 21,4% до 25,0%**. В каждом из 1000 повторов выбирали магазины с возвращением и брали все дни выбранного магазина вместе. Этот интервал описывает неопределенность на выбранном окне. Изменчивость во времени смотрим по отдельным окнам.

| Окно | RMSPE без истории | RMSPE с историей |
|---|---:|---:|
| 28.03 по 08.05.2015 | 23,39% | 18,74% |
| 09.05 по 19.06.2015 | 21,27% | 16,90% |
| 20.06 по 31.07.2015 | 20,33% | 15,61% |
| Среднее ± стандартное отклонение | 21,66% ± 1,57 п.п. | 17,09% ± 1,57 п.п. |

Если на основном окне оставить только 856 магазинов из `test.csv`, остается **30 960** строк с положительной выручкой. RMSPE снижается с **18,36% до 14,96%**, или на **18,5%** относительно модели без истории. Величина эффекта зависит от состава магазинов.

### Линейная регрессия с L2-регуляризацией

Отдельно проверили штраф на большие коэффициенты с заранее фиксированным `alpha=100`. Использовали те же признаки, строки и правила оценки.

| Набор признаков | RMSPE без регуляризации | RMSPE с L2 |
|---|---:|---:|
| Без истории | 20,33% | 21,02% |
| С историей | 15,61% | 15,73% |

При `alpha=100` RMSPE вырос в обеих версиях. У модели с историей MAE снизилась с **754,71** до **749,35**. По основной метрике из этих двух вариантов выбираем линейную регрессию без регуляризации.

### Примеры ошибок

Для каждого из трех срезов взяли по одному примеру около 90-го перцентиля абсолютной относительной ошибки модели с историей.

| Срез | Магазин и дата | Факт | Прогноз | Ошибка |
|---|---|---:|---:|---:|
| Низкая выручка | 852, 27.06.2015 | 2385 | 3408 | +42,9% |
| Промодень | 795, 30.06.2015 | 7104 | 5555 | −21,8% |
| Обычный день | 913, 06.07.2015 | 6829 | 8246 | +20,8% |

На нижних 10% положительной выручки RMSPE модели с историей составил **28,40%**. В этом срезе модель завышает прогноз в **76,0%** случаев. На срез приходится **33,1%** суммы квадратов относительных ошибок при примерно **10%** оцененных строк. На остальных промоднях RMSPE равен **13,52%**, на остальных обычных днях **13,42%**. Подробности, графики по срезам и пример прогноза магазина есть в [ноутбуке с анализом](notebooks/analysis.ipynb).

## 7. Исследовательские вопросы

1. **Помогает ли информация о тренде?** Сравнили полную модель с той же моделью без тренда. RMSPE почти совпал. Получили **15,613%** с трендом и **15,607%** без него. MAE с трендом ниже. По основной метрике пользы на этом окне не видно.
2. **Добавляют ли прошлогодние продажи полезную информацию?** Сравнили полную модель с версией без этого признака на **35 252** строках с доступным прошлогодним наблюдением. RMSPE снизился с **16,23% до 15,59%**.
3. **Насколько прогноз чувствителен к разовым всплескам в истории?** Всплеском считали день с выручкой хотя бы втрое выше исторической медианы для магазина и дня недели. У **38** магазинов такие дни были, но занимали не больше 1% положительной истории. Исключили **55** таких строк из истории до окна, пересчитали признаки и заново спрогнозировали те же дни той же обученной моделью. На **1363** строках с положительной выручкой медиана абсолютного изменения прогноза составила **1,7** единицы выручки, а 90-й перцентиль составил **10,6**. RMSPE изменился с **20,34% до 20,30%**. При таком определении всплеска изменение прогноза обычно небольшое. В отдельной проверке агрегата среднее по магазину и дню недели дало **20,08% RMSPE** на том же срезе, а медиана дала **20,34%**.

   Были и отдельные сильные изменения. У магазина 303 на 14 июля прогноз снизился с **9334 до 7006** при факте **7797**. После удаления всплеска признак продаж год назад сменился с **27 318** на медиану **6281**.

## 8. Выводы

Основная гипотеза получила поддержку. Снижение RMSPE превысило 5% и повторилось на всех трех окнах. Из отдельных проверок самый ясный выигрыш дали прошлогодние продажи. Самым трудным остается срез с низкой выручкой. Вариант со средним показал самый низкий RMSPE на последнем окне (**15,41%**), поэтому его стоит отдельно проверить на более ранних окнах перед выбором в качестве следующего baseline.

Оценка относится к истории одной сети и трем окнам в 2015 году. Календарные эффекты в линейной модели в основном общие для магазинов. В следующем эксперименте проверим, помогает ли отдельный признак отсутствия прошлогоднего наблюдения на строках, где приходится заменять его исторической медианой.

## Воспроизведение

1. Скачать архив Rossmann на Kaggle и распаковать его в `data/`. Для запуска нужны `data/train.csv` и `data/test.csv`. Обучение и расчет ошибок используют только `train.csv`. [Скачать данные](https://www.kaggle.com/c/rossmann-store-sales/data?select=train.csv)
2. Из корня проекта выполнить команды в PowerShell. Проверено на Python 3.13.7. Обучение идет на CPU с фиксированным числом потоков BLAS.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.run_baseline --config configs/baseline.json
```

Команда сохраняет метрики в `artifacts/baseline/metrics.json`, прогнозы в `artifacts/baseline/predictions.csv`. После запуска можно открыть [ноутбук](notebooks/analysis.ipynb) или пересчитать его командой ниже.

```powershell
.\.venv\Scripts\python.exe -m nbconvert --to notebook --execute --inplace notebooks/analysis.ipynb
```

| Путь | Содержимое |
|---|---|
| `configs/baseline.json` | Пути, горизонт, порог улучшения и настройки повторной оценки |
| `src/data.py` | Загрузка данных, временные окна и признаки |
| `src/train.py` | Обучение и прогноз линейной регрессии |
| `src/evaluate.py` | Метрики, сводка данных и бутстрап |
| `src/run_baseline.py` | Запуск всех сравнений |
| `notebooks/analysis.ipynb` | Графики и интерпретация результатов |
