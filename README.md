# Rossmann Store Sales | ДЗ1 по ML R&D

На последних 42 днях в `train.csv` модель с историей продаж снизила RMSPE с **20,33% до 15,61%**. Ошибка стала на **23,2% ниже** при пороге улучшения 5%.

## 1. Постановка задачи

Прогнозируем дневную выручку каждого магазина Rossmann на шесть недель вперед. Такой прогноз помогает планировать график сотрудников. Для каждого магазина строим прогноз сразу на все 42 дня. Горизонт взяли из описания контеста. [Rossmann Store Sales на Kaggle](https://www.kaggle.com/c/rossmann-store-sales)

Основную проверку проводим на 1115 магазинах из `train.csv`. В официальном `test.csv` 48 дней, с 1 августа по 17 сентября 2015 года, и 856 магазинов. Из этого файла берем список магазинов для дополнительной проверки на тех же 42 днях из `train.csv`.

> **Гипотеза.** Если добавить к линейной регрессии признаки прошлых продаж, рассчитанные только по данным до начала основного 42-дневного окна, RMSPE на этом окне снизится как минимум на 5% относительно той же модели без этих признаков.
>
> Базовая модель учитывает типичный уровень продаж каждого магазина и общий для сети недельный профиль. История помогает учесть, как продажи меняются по дням недели в конкретном магазине.

Обе версии линейной регрессии используют магазин, календарь и запланированное промо. Во вторую добавляем шесть признаков из истории продаж. Сравниваем версии на одних и тех же строках. Порог выбрали до эксперимента.

## 2. Формализация

| Что | Определение |
|---|---|
| Тип задачи | Прогноз по нескольким временным рядам, по одному на магазин |
| Единица наблюдения | Один день одного магазина (`Store`, `Date`) |
| Цель `y` | Дневная выручка `Sales` |
| Признаки `X` | Номер магазина, день недели, месяц и запланированная акция. Для второй модели добавляем данные о прошлых продажах |
| Одно предсказание | Сколько выручки получит магазин в этот день. Если магазин не будет работать, прогноз равен нулю |

В момент прогноза считаем, что на все 42 дня уже известны запланированные акции (`Promo`) и дни, когда магазин будет работать (`Open`). При `Open = 0` ставим прогноз 0, потому что в этот день магазин не работает. В `test.csv` у магазина 622 значение `Open` пропущено в 11 строках. Для прогноза в контесте нужно будет решить, как обрабатывать такие случаи.

## 3. Данные и их анализ

В `train.csv` **1 017 209** строк по **1115** магазинам, с 1 января 2013 по 31 июля 2015. Для каждого дня записаны выручка, число покупателей, работал ли магазин, была ли акция и был ли праздник. Один магазин встречается в каждой дате максимум один раз. Во всех имеющихся строках поля заполнены. [Описание данных](https://www.kaggle.com/c/rossmann-store-sales/data?select=sample_submission.csv)

- У **180 магазинов** нет записей ни за один из **184 дней** с 1 июля по 31 декабря 2014 года. Из-за таких пропусков продажи за дату год назад доступны не всегда. В основном окне таких случаев **5030** среди дней с положительной выручкой. Как заполняем пропуски, описано в разделе 4. [Обсуждение данных на Kaggle](https://www.kaggle.com/c/rossmann-store-sales/forums/t/16856/missing-data-180-stores-several-months/95225)
- В **172 871** строке выручка равна нулю. В **172 817** случаях магазин в этот день не работал. Еще в **54** случаях магазин был открыт, но выручка все равно записана как нулевая.
- Примерно **93%** положительных значений дневной выручки лежат между **2000** и **12 000**, медиана равна **6369**. Отдельно проверяем, насколько редкие всплески влияют на прогноз.
- Чтобы избежать утечки, строим прогноз только по информации, доступной на тот момент. Например, фактическое число покупателей (`Customers`) и выручку за дни, которые предстоит спрогнозировать, узнаем позже. Для проверки откладываем последние даты целиком.

Распределение выручки и сравнение дней с акциями и без них показаны в ноутбуке. [Графики и разбор данных](notebooks/analysis.ipynb)

## 4. Базовая модель

Сравниваем две версии **линейной регрессии**. Первая использует магазин, день недели, месяц и признак акции `Promo`. Вторая дополнительно получает шесть признаков из прошлых продаж.

| Исторический признак | Как считаем до даты прогноза |
|---|---|
| Медиана магазина | Медиана положительных продаж магазина |
| Медиана по магазину и дню недели | Медиана положительных продаж для того же дня недели |
| Недавняя выручка | Средняя положительная выручка за последние 28 дней |
| Тренд | Разница между средней положительной выручкой за последние 28 дней и за предыдущие 28 дней |
| Продажи год назад | Выручка за дату на 364 дня раньше, чтобы сохранить день недели |
| Типичная выручка во время акций | Медиана положительной выручки за прошлые дни с акциями. Для будущих дней без акции значение признака равно нулю |

Если данных для отдельной группы или периода нет, подставляем медиану магазина. Если нет и ее, берем медиану по всем магазинам. Когда выручка за дату год назад неизвестна, подставляем типичную выручку этого магазина в тот же день недели. Для тренда нужны оба 28-дневных периода. Если одного из них нет, ставим ноль.

Для магазина, дня недели и месяца используем one-hot кодирование. Числовые признаки приводим к сопоставимому масштабу. Обучаем обе модели на днях с положительной выручкой и подаем в качестве цели `log1p(Sales)`. После прогноза возвращаемся к единицам выручки через `expm1` и заменяем отрицательные значения нулем. У обеих моделей одинаковые настройки, включая свободный член. Так можно сравнить эффект от добавления истории.

## 5. Протокол оценки

Основной период проверки длится **с 20 июня по 31 июля 2015 года**. За эти 42 дня есть **46 830** строк, из них **40 282** с положительной выручкой. Еще два более ранних периода по 42 дня помогают проверить, повторяется ли результат.

1. Для обучения разбиваем прошлые даты на периоды по 42 дня. Для каждого периода считаем исторические признаки только по продажам до его начала. В основном эксперименте обучаемся на **747 397** строках с положительной выручкой, со 2 марта 2013 по 19 июня 2015. Данные до 2 марта нужны для расчета первых признаков.
2. Кодирование категорий и масштабирование числовых признаков настраиваем только на обучающих данных. Обе модели оцениваем на одних и тех же магазинах и датах.
3. **RMSPE** измеряет ошибку относительно фактической выручки. Считаем `(прогноз - факт) / факт` для каждой строки, возводим ошибки в квадрат, усредняем и берем корень. Как в контесте, в расчет входят дни с положительной выручкой. На тех же строках считаем **MAE**, среднюю абсолютную ошибку в единицах выручки. [Правила расчета RMSPE](https://www.kaggle.com/c/rossmann-store-sales)
4. Основную гипотезу проверяем на двух заранее выбранных версиях по RMSPE. Остальные сравнения отвечают на исследовательские вопросы.

## 6. Результаты

| Вариант | RMSPE | MAE |
|---|---:|---:|
| Линейная регрессия без исторических признаков | 20,33% | 931,78 |
| Линейная регрессия с историческими признаками | 15,61% | 754,71 |

На последних 42 днях RMSPE снизился на **4,72 процентного пункта**, или на **23,2% относительно модели без истории**. Чтобы оценить, насколько результат зависит от состава магазинов, 1000 раз случайно выбирали магазины с возможностью повторов и брали все дни каждого выбранного магазина. Получили 95%-й бутстрап-интервал **от 21,4% до 25,0%**. Отдельные периоды ниже показывают, как меняется результат во времени.

| Окно | RMSPE без истории | RMSPE с историей |
|---|---:|---:|
| 28.03 по 08.05.2015 | 23,39% | 18,74% |
| 09.05 по 19.06.2015 | 21,27% | 16,90% |
| 20.06 по 31.07.2015 | 20,33% | 15,61% |
| Среднее ± стандартное отклонение | 21,66% ± 1,57 п.п. | 17,09% ± 1,57 п.п. |

Среди 856 магазинов из `test.csv` на тех же 42 днях есть **30 960** строк с положительной выручкой. Для этих магазинов добавление истории снижает RMSPE с **18,36% до 14,96%**, или на **18,5%**.

### Линейная регрессия с L2-регуляризацией

Отдельно проверили L2-регуляризацию. Она добавляет штраф за большие коэффициенты модели. Взяли `alpha=100` и повторили сравнение на тех же данных.

| Набор признаков | RMSPE без регуляризации | RMSPE с L2 |
|---|---:|---:|
| Без истории | 20,33% | 21,02% |
| С историей | 15,61% | 15,73% |

При `alpha=100` RMSPE вырос у обеих моделей. У модели с историей средняя абсолютная ошибка при этом снизилась с **754,71** до **749,35**. Поскольку сравниваем по RMSPE, выбираем линейную регрессию без регуляризации.

### Примеры ошибок

Для каждой группы взяли по одному примеру, где модель с историей ошиблась сильнее, чем примерно в 90% случаев в этой группе.

| Срез | Магазин и дата | Факт | Прогноз | Ошибка |
|---|---|---:|---:|---:|
| Низкая выручка | 852, 27.06.2015 | 2385 | 3408 | +42,9% |
| День с акцией | 795, 30.06.2015 | 7104 | 5555 | −21,8% |
| День без акции | 913, 06.07.2015 | 6829 | 8246 | +20,8% |

На 10% дней с самой низкой положительной выручкой RMSPE модели с историей равен **28,40%**. В этой группе прогноз выше факта в **76,0%** случаев. На нее приходится **33,1%** суммы квадратов относительных ошибок. Среди остальных дней RMSPE равен **13,52%** с акциями и **13,42%** без акций. [Графики и пример прогноза магазина](notebooks/analysis.ipynb)

## 7. Исследовательские вопросы

1. **Помогает ли информация о тренде?** На этом периоде RMSPE почти одинаковый: **15,613%** с трендом и **15,607%** без него. MAE с трендом немного ниже.
2. **Добавляют ли прошлогодние продажи полезную информацию?** На **35 252** строках, где есть выручка за дату год назад, добавление этого признака снизило RMSPE с **16,23% до 15,59%**.
3. **Насколько прогноз чувствителен к разовым всплескам в истории?** Считали выручку всплеском, если она хотя бы втрое выше медианы для этого магазина и дня недели. У **38** магазинов такие дни занимали до 1% дней с положительной выручкой. Убрали из истории **55** всплесков, пересчитали признаки и заново получили прогнозы той же обученной модели. На **1363** строках с положительной выручкой половина прогнозов изменилась максимум на **1,7** единицы, а 90% прогнозов изменились максимум на **10,6**. RMSPE снизился с **20,34% до 20,30%**. Отдельно сравнили среднее и медиану выручки по магазину и дню недели. На тех же строках среднее дало **20,08% RMSPE**, медиана дала **20,34%**.

   Самое заметное изменение было у магазина 303 на 14 июля. Прогноз снизился с **9334 до 7006**, фактическая выручка составила **7797**. Всплеск пришелся на дату, из которой брали продажи год назад. После его удаления вместо **27 318** модель получила медиану **6281**.

## 8. Выводы

На всех трех периодах история продаж снизила RMSPE больше чем на 5%. Среди проверенных отдельно признаков прошлогодние продажи дали самый заметный выигрыш. Больше всего модель ошибалась в дни с низкой выручкой. Вариант со средним показал **15,41% RMSPE** на последнем периоде. Чтобы выбрать его для дальнейшей работы, нужно проверить результат и на более ранних датах.

Проверка охватывает одну сеть и три периода в 2015 году. Следующий вопрос: станет ли прогноз точнее, если отдельно сообщить модели, что продажи год назад пришлось заменить медианой?

## Воспроизведение

1. Скачать архив Rossmann на Kaggle и распаковать его в `data/`. Для запуска нужны `data/train.csv` и `data/test.csv`. Обучение и расчет ошибок используют только `train.csv`. [Скачать данные](https://www.kaggle.com/c/rossmann-store-sales/data?select=train.csv)
2. Из корня проекта выполнить команды в PowerShell. Проверено на Python 3.13.7. Обучение идет на CPU с фиксированным числом потоков BLAS.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.run_baseline --config configs/baseline.json
```

Команда сохраняет метрики в `artifacts/baseline/metrics.json`, прогнозы в `artifacts/baseline/predictions.csv`. После запуска можно открыть [ноутбук](notebooks/analysis.ipynb) или пересчитать его командой ниже.

```powershell
.\.venv\Scripts\python.exe -m nbconvert --to notebook --execute --inplace notebooks/analysis.ipynb
```

| Путь | Содержимое |
|---|---|
| `configs/baseline.json` | Пути, горизонт, порог улучшения и настройки повторной оценки |
| `src/data.py` | Загрузка данных, временные окна и признаки |
| `src/train.py` | Обучение и прогноз линейной регрессии |
| `src/evaluate.py` | Метрики, сводка данных и бутстрап |
| `src/run_baseline.py` | Запуск всех сравнений |
| `notebooks/analysis.ipynb` | Графики и интерпретация результатов |
